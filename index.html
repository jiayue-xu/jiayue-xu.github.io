Overview

分布式训练将模型训练负载分配到多个工作节点上，从而提升训练速度和模型准确率。尽管分布式训练可以被用于任何类型的机器学习模型，但对计算密集型的大模型优化更明显，比如深度学习。

教程给了两个使用torch.distributed.rpc的分布式训练示例，源码可以在示例代码找到。

有时候，你的训练模型比较特别，常见的分布式数据并行不太适用，比如：

  1. 在增强学习中，模型本身比较小，并且从环境中获取训练数据代价也比较大。在这种情况下，让多个观察者并行运行同时共享单个代理进程会比较合适，代理进程负责在本地进行训练，但是也需要在训练者和观察者之间进行数据通信。
  2. 你的模型可能很大，单台机器的GPU卡无法适配，此时可能需要将模型拆开到不同的机器上运行。或者你可能需要实现一个参数服务器训练框架，模型参数和训练者在不同的机器上。

torch.distributed.rpc适用于以上场景，在示例1中RPC和RRef允许从一个worker发送数据到另一个worker，并且轻松地引用远程数据对象。在示例2中，分布式自动评分和自动优化器让反向传播和优化步骤就像在本地执行一样。接下来给出对应的案例。

Efficient Sparse Collective Communication and its application to Accelerate Distributed Deep Learning

发表于 2024-05-08 更新于 2026-01-18 本文字数： 1.2k 阅读时长 ≈ 2 分钟

高效的集体通信对于大规模推荐系统的分布式训练和自然语言处理模型等并行计算应用至关重要。现有的集体通信库侧重于对密集输入的优化操作，导致在输入稀疏时传输许多零。这与当前在大型模型中数据稀疏性不断增加的趋势相悖。

我们提出了一种高效的流式聚合系统Omni Reduce，它利用稀疏性，通过只发送非零数据块来最大化有效带宽的使用。我们证明了这一想法是有益的，并将分布式训练加速了高达8.2 ×。即使在100Gbps速率下，OmniReduce为网络瓶颈DNN提供了1.4 - 2.9倍的性能提升。

Introduce

集群通信例程(或者简单地说,集体)是并行计算应用的核心构建块。集合通常用于合并多个并行执行操作的进程之间的数据。在几乎所有的场景中，实现高性能的集体通信是至关重要的，因为不利的计算与通信比例限制了有效地扩展工作负载的能力。

其中一个场景，也是本文研究的重点，分布式深度学习(Distributed Deep Learning，DDL)，被广泛应用于加速大型深度神经网络(deep neural networks，DNNs)的训练，通过GPU或其他AI加速器(例如, TPUs)在大量worker上并行训练。最常见的DDL方法是基于随机梯度下降(SGD)的数据并行训练。分布式SGD是一个并行的、迭代的、分两步的工作负载：

  1. 每个worker通过并行处理不同子集(mini-batch)的训练数据来训练模型的局部副本；
  2. 所有的工人在下一次迭代之前，将他们的计算结果(即,局部梯度)结合起来，产生一个应用于模型的平均梯度。

将SGD分配给多个worker时，可以保持每次迭代的mini-batch总量不变(强缩放)，也可以将mini-batch随worker数量线性增加(弱缩放)。前一种情况下，当每个工人的梯度大小保持不变时，计算时间减少；因此，培训很快就变成了沟通的束缚。在后一种情况下，计算通信比(理想情况下)保持不变。然而，在现实中，由于扩展开销，通信时间随着工人数量的增加而增加。此外，大量的小批量会降低训练质量。为了实现更好的扩展，我们的目标是通过优化集体通信来减少通信开销。从图1可以看出，这些开销在许多DNN工作负载中都是相当大的，特别是在大型模型中，测量性能与理想的线性缩放之间存在显著差距。

现有的大多数集合通信库——包括NCCL、Gloo等DDL专用集合通信库，都没有针对稀疏数据的原生支持。这些库假设密集的输入数据，并低效地利用宝贵的网络带宽传输大量的零。一般来说，这也是梯度压缩方法的一个限制，因为它们的实现在调用一个集合例程之前首先将稀疏的数据聚集成类稠密的格式(它具有开销) 。

我们的关键创新在于设计了针对稀疏数据的高效集合运算。我们提出了OmniRereduce，一个流聚合系统，旨在最大限度地提高带宽的利用效率，并作为传统集体库的替代品。OmniRereduce利用输入数据的稀疏性来减少通信量。

Accelerating Distributed Deep Learning using Multi-Path RDMA in Data Center Networks

发表于 2024-05-06 更新于 2026-01-18 本文字数： 1.5k 阅读时长 ≈ 3 分钟

数据中心网络(Data Center Networks，DCNs)广泛部署了RDMA以支持机器学习等数据密集型应用。虽然DCN具有丰富的多路径拓扑结构，但目前的RDMA技术在硬件上不支持多路径传输。在本文中，我们提出了一种基于纯软件的多路径RDMA解决方案——Maestro，以有效地利用丰富的多路径拓扑来实现负载均衡和可靠性。Maestro作为运行在用户空间的”中间件”，具有模块化和软件定义的特点：Maestro将路径选择和负载均衡机制与硬件特性解耦，允许DCN运营商和应用根据需要采用最佳机制进行灵活决策。因此，Maestro可以很容易地使用现有的RDMA硬件(NICs)来部署，以支持分布式深度学习(DDL)应用。我们的实验表明，Maestro能够充分利用多条路径，而CPU开销可以忽略不计，从而提高了DDL应用的性能。

1 INTRODUCTION

RoCE已被广泛部署在DCNs中，以支持分布式机器学习和深度学习等数据密集型应用。RDMA/RoCE采用内核旁路和零拷贝技术，允许应用程序直接从一个服务器的(用户空间)主存中读或写大块数据到另一个服务器的主存中。这是通过”卸载传输”到专用的RDMA网络接口卡(简称RNIC)来实现的，RNIC直接在网卡硬件缓冲区和应用用户空间内存区域之间传输数据，从而显著降低内核处理开销和远程内存访问延迟。RoCE利用标准栈( TCP/IP协议)建立控制路径，包括在两个通信应用程序的两端建立所谓的队列对(Queue Pairs，QPs)，并对内存区域进行注册。对于数据通路操作，应用程序使用RDMA Verbs(例如SEND/RECV, WRITE/READ方法等)进行数据传输：相应的RNIC会自动从用户空间内存区域中取出需要传输的数据块，将其分割并封装成UDP/IP数据包，并通过网络进行传输。通过设计，RDMA是一种点到点的传输，其中每个RDMA连接(Queue Pair)被映射到单个网络路径(由RNICs的IP地址对指定或由硬件跟踪产生的UDP流)上。

数据密集型的RDMA工作负载往往表现为大数据块的周期性传输。例如，分布式深度学习应用，例如使用内置RDMA支持的PyTorch或TensorFlow实现，需要在一个DCN中运行的多个实例之间进行周期性的参数同步，这通常涉及一次传输10次或100次MB或数GB的数据。在这段时间内，网络链路利用率显著增加：与数据传输相关的”大象流”不仅相互竞争网络带宽，造成拥塞，而且严重影响与RDMA控制消息或其他应用相关的”老鼠流”的(尾部)延迟。另一方面，现代DCN采用”脊-叶”拓扑结构，具有丰富的路径多样性。遗憾的是，目前的点对点RDMA传输无法利用这种丰富的多路径拓扑进行智能负载均衡来缓解拥塞(特别是沿着被超额使用的核心路径)，减少整体流的完成时间。

在本文中，我们提出了一个完全基于软件的多路径RDMA传输框架。通过解决上述挑战，我们的解决方案采用了三个关键的创新。首先，本文提出了一种新颖的基于虚拟RNIC的用户空间路径控制机制。我们创建多个虚拟接口，每个都有一个不同的虚拟IP地址，并将它们绑定到同一个物理RNIC。其次，我们开发了一个用户空间中间件层，将RDMA操作的(大)消息截获并拆分为多个(小)消息，并在发送端动态地映射到不同的路径上，在接收端通过将它们传递到应用程序而不引入额外的内存拷贝来明智地将它们合并在一起。正确地执行这些操作并引起尽可能少的开销(特别地,保持零拷贝)是非平凡的；它们包括精心设计和一些巧妙的技巧(见§ 3)。第三，我们解耦了路径映射(和选择)，路径监控和负载均衡机制，以允许灵活性并实现应用程序感知的负载均衡。

Raft是一个相对更易理解的一致性协商(consensus)算法，能让一组机器作为一个整体进行工作，并且具有一定的容错能力。

为了避免脑裂问题，Raft采用了半数票决的方式执行操作，即当过半的机器能够成功执行一个操作，那么领导者就认为该操作是可行的。
